# 仿真验证结果（2026-10-28）

结论：基本导航通过；受控动态避障未通过，不能认定完整仿真跑通。

环境：RTX 2060，CUDA Toolkit 12.8，PyTorch 2.4.1+cu121，epoch60.pth，nav 模式。
验证直接发布 `/move_base_simple/goal`，与 RViz 2D Nav Goal 使用相同接口；未启动 RViz GUI。

## 基本导航

默认随机柱状地图、默认动态圆柱场景，目标 `(8, 0, 0.6)`，记录 35 秒。

- 约 10 秒内进入配置的 2 米三维到达半径。
- 最终位置约 `(7.009, 0.452, 1.405)`，三维误差约 1.354 米。
- 飞行高度范围约 1.067–1.966 米，未落地。
- 实际轨迹到静态地图采样点的最小距离约 0.672 米。这是点云距离，不是连续几何碰撞证明。
- 仿真碰撞计数为 0；默认柱状地图并未全部纳入仿真静态碰撞计数，因此另行计算上述点云距离。
- 稳态雷达、感知、推理和轨迹提交约 10 Hz；有少量超过 120 ms 的结果被丢弃。
- 默认到达半径为 2 米，本次未验证精确降到 0.6 米并停在目标中心。

数据：`navigation.json`、`navigation.log`、`navigation-policy.log`。

## 动态避障

独立空旷 arena 场景，从全新动力学、感知、规划节点启动。
发送 `(20, 0, 0.6)` 目标，3 秒后通过 `/clicked_point` 生成一颗正面碰撞航线球：
球半径 0.2 米、速度 3.5 m/s、提前量 2.5 秒。

- 跟踪器曾确认 1 个目标。
- 碰撞计数从 0 增至 1（动态碰撞）。
- 根据障碍 marker 和最新里程计估计的最小表面间距约 -0.347 米；正式失败依据是仿真碰撞计数。
- 来袭期间感知处理出现数百毫秒延迟，完整感知帧和轨迹提交一度降到 0 Hz，无人机未完成有效避让。
- 因而本次动态测试失败，感知延迟与规划帧时效限制之间的问题还需进一步定位；没有放宽时效限制来掩盖问题。

此前 2.5 m/s 测试也碰撞，但其速度低于当前 tracker 的 3 m/s 过滤阈值，且切换地图未重置感知，因此保留记录，不作为干净独立测试。

数据：`dynamic-3.5mps.json`、`dynamic-3.5mps.log`、`dynamic-policy.log`、`dynamic-detector.log`、`dynamic-sensor.log`、`dynamic-scenario.yaml`。

## 本次修复

- M-detector 缓冲区只支持 30,000 点，实测雷达达到 30,240 点并触发 SIGSEGV：容量调为 40,000，增加超限保护。
- 起飞服务后台线程改为复制请求，避免服务返回后引用失效。
- 已在空中时跳过 OmniRisk 的重复起飞请求。
- 仿真控制器质量从 0.77 kg 修正为机体使用的 0.98 kg，并支持 ROS mass 参数。
- `/lidar_points` 仿真输入按机体坐标处理。
- Simulator 支持 `_config_file:=...`，测试场景使用独立 YAML，默认场景未改动。

Controller、ros_ws、Simulator 增量编译通过，`git diff --check` 通过。测试后停止本次启动的仿真节点。
